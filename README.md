# Web Agent — ACP Bridge & Web UI

Веб-клиент и Node.js-мост для работы с AI-агентом через **Agent Client Protocol (ACP)** (`agy acp`) на удалённом сервере через браузер.

Проект создан для комфортной работы с агентом с десктопа и телефона (включая доступ по обычному HTTP внутри VPN-сети, например Amnezia VPN, без HTTPS/Secure Context).

---

## Требования

- **Node.js** (проверено на v22 LTS) и **npm**
- Установленный CLI-агент **`agy`** (или другой ACP-совместимый агент), доступный в `PATH`
- Пройденная авторизация агента на машине, где запускается мост (если требуется провайдером, например `agy acp --login`)

---

## Локальный запуск и разработка

1. Установите зависимости для бэкенда и фронтенда:

   ```bash
   npm install
   npm --prefix web install
   ```

2. Запустите мост в dev-режиме (передав рабочий каталог через `ACP_SANDBOX_DIR` или `--cwd`):

   ```bash
   # Linux / macOS
   ACP_SANDBOX_DIR=/tmp/sandbox npm run dev

   # или через CLI-флаг (удобно и в Windows)
   npm run dev -- --cwd /tmp/sandbox
   ```

   > Примечание: в Windows для локальной отладки UI можно подменить `--command` и `--args` на тестовый скрипт или запустить реальный `agy`, если он установлен в системе.

3. В отдельном терминале запустите Vite dev-сервер для фронтенда:

   ```bash
   npm run web:dev
   ```

   Интерфейс откроется на `http://localhost:5173`. Запросы к `/ws` и `/files` автоматически проксируются на `127.0.0.1:3001` (настроено в [`web/vite.config.ts`](web/vite.config.ts)).

Проверка типов, прогон всех тестов (Vitest) и сборка производственных бандлов:

## Развёртывание на сервере (Ubuntu + systemd + Nginx)

В репозитории лежат готовые шаблоны в директории [`deploy/`](deploy) и скрипт [`scripts/build-web.sh`](scripts/build-web.sh).

### 1. Бэкенд (`acp-bridge.service`)

1. Соберите проект (`npm run build`) и разместите файлы (`dist/`, `package.json`, `node_modules/` — через `npm ci --omit=dev`) в `/opt/web-agent`.
2. Убедитесь, что `agy` установлен и авторизован под тем пользователем, от которого запускается сервис (в шаблоне [`deploy/acp-bridge.service`](deploy/acp-bridge.service) это `root`, `PATH` включает `/root/.local/bin`, рабочая директория песочницы — `/srv`).
3. Установите и включите unit:

   ```bash
   cp deploy/acp-bridge.service /etc/systemd/system/acp-bridge.service
   systemctl daemon-reload
   systemctl enable --now acp-bridge
   systemctl status acp-bridge
   ```

### 2. Фронтенд и Nginx

1. Соберите статику веб-клиента и положите в `/opt/acp-web/dist-web` (можно воспользоваться скриптом `scripts/build-web.sh` на сервере или скопировать локально собранный `web/dist/*`):

   ```bash
   ./scripts/build-web.sh
   ```

2. Подключите конфиг [`deploy/nginx-acp-ui.conf`](deploy/nginx-acp-ui.conf) (по умолчанию слушает внутренний VPN-адрес `172.29.172.1:7682`, отключена буферизация для `/ws`, выставлен `Cache-Control: no-store` для `index.html` и проксируются `/ws` и `/files` на `127.0.0.1:3001`):

   ```bash
   cp deploy/nginx-acp-ui.conf /etc/nginx/sites-available/acp-ui.conf
   ln -sf /etc/nginx/sites-available/acp-ui.conf /etc/nginx/sites-enabled/acp-ui.conf
   nginx -t && systemctl reload nginx
   ```

## Конфигурация

Настройки задаются через переменные окружения (см. [`src/config.ts`](src/config.ts)) или CLI-флаги при запуске [`src/index.ts`](src/index.ts).

### Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
| --- | :---: | --- | --- |
| `ACP_SANDBOX_DIR` | Да | — | Существующая рабочая директория по умолчанию (`cwd`) для запуска агента (например, `/srv`). |
| `ACP_BRIDGE_HOST` | Нет | `127.0.0.1` | Адрес прослушивания. Разрешены только loopback-адреса (`127.0.0.1`, `::1`, `localhost`). |
| `ACP_BRIDGE_PORT` | Нет | `3001` | TCP-порт моста (WebSocket + HTTP `/files`). |
| `ACP_BRIDGE_WS_PATH` | Нет | `/ws` | URL-путь для WebSocket-подключений (остальные, кроме `/files`, возвращают `404`). |
| `ACP_COMMAND` | Нет | `agy` | Исполняемый файл агента. |
| `ACP_ARGS` | Нет | `acp` | Аргументы запуска агента (разделяются по пробелам). |
| `ACP_SHUTDOWN_GRACE_MS` | Нет | `3000` | Время ожидания (мс) после `SIGTERM` до принудительного `SIGKILL` процесса агента. |
| `ACP_MAX_LINE_BYTES` | Нет | `16777216` (16 МБ) | Максимальный размер одного JSON-RPC сообщения / WS-фрейма. |
| `ACP_HEARTBEAT_MS` | Нет | `30000` | Интервал (мс) отправки серверных WebSocket ping-фреймов (`0` отключает). |
| `ACP_DETACHED_TIMEOUT_MS` | Нет | `900000` (15 мин) | Сколько ждать переподключения клиента при активном запросе перед завершением агента. |
| `ACP_MAX_REPLAY_BUFFER_LINES` | Нет | `2000` | Максимум NDJSON-строк, сохраняемых в `detachedBuffer` при отсутствии сокета. |
| `ACP_VIEWER_MAX_BYTES` | Нет | `1048576` (1 МБ) | Максимальный размер файла для полного открытия в `/files` без режима `head`/`tail`/`download`. |
| `ACP_VIEWER_SNIPPET_BYTES` | Нет | `102400` (100 КБ) | Объём данных, читаемый в режимах `?head=1` и `?tail=1`. |

### CLI-флаги

Флаги имеют приоритет над переменными окружения:

- `--host <host>`
- `--port <port>`
- `--ws-path <path>`
- `--command <bin>`
- `--args "<arg1 arg2>"`
- `--cwd <dir>`

## Зачем нужен этот проект

Стандартный CLI-агент общается через NDJSON по `stdio`, а готовые веб-обёртки ломаются при работе по HTTP-IP и на нестабильном мобильном интернете. **Web Agent** решает эти проблемы:

1. **Надёжный NDJSON ↔ WebSocket мост (`src/`)**
   - Принимает подключения строго на loopback-интерфейс (`127.0.0.1` / `::1` / `localhost`) — наружу торчит только Nginx.
   - Инкрементально декодирует и буферизует `stdout` агента до `\n`: крупные JSON-RPC ответы (до 16 МБ) не рвутся по границам TCP/WebSocket-фреймов.
   - Пропускает клиентский heartbeat `$/ping` без передачи его агенту и поддерживает соединение серверными WebSocket ping-фреймами.
2. **Устойчивость к блокировке экрана, обрыву связи и `F5`**
   - **Detached-режим:** при закрытии вкладки, потере VPN или блокировке экрана телефона во время генерации ответа (`session/prompt`) или ожидания подтверждения (`session/request_permission`) процесс агента не убивается, а все выходящие события копятся в кольцевом буфере (`detachedBuffer`). При переподключении клиент получает пропущенные чанки.
   - **Параллельный реплей истории при перезагрузке:** `agy acp` прерывает активный `session/prompt`, если в тот же процесс отправить `session/load`. Мост при получении `session/load` во время активной генерации поднимает временный изолированный процесс-ридер `agy acp`, мгновенно вычитывает историю переписки из базы сессии и сразу следом досылает буфер и живой поток текущей генерации.
3. **Кастомный веб-клиент на React (`web/`)**
   - Работает по обычному `http://` без Secure Context (собственный генератор UUID v4 поверх `crypto.getRandomValues`, fallback-копирование в буфер обмена через `document.execCommand("copy")`).
   - Не обрывает долгие запросы таймаутом (клиентские `session/prompt` и `session/load` работают без искусственного ограничения по времени).
   - Адаптивная вёрстка под мобильные экраны, тёмная и светлая темы.
4. **Встроенный HTTP-просмотрщик файлов (`/files`)**
   - Любые ссылки `file:///...` в ответах агента, а также пути к файлам в вызовах инструментов и окнах подтверждений автоматически преобразуются в `/files?path=...`.

## Основные возможности

### Веб-интерфейс чата

- **Стриминг ответа и шагов:** отображение текста (`MarkdownView` с подсветкой синтаксиса через `highlight.js` и кнопками копирования кода), мыслей агента (`agent_thought_chunk`) и карточек вызова инструментов (`tool_call`, `tool_call_update`). В свёрнутом состоянии шаг размышлений показывает первую непустую строку с обрезкой.
- **Подтверждение действий (`PermissionModal`):** перехват `session/request_permission`, отображение параметров и затрагиваемых файлов со ссылками на просмотрщик, сохранение ожидающего запроса при обрыве соединения.
- **Управление сессиями (`SessionSidebar`):** создание нового чата, переключение, переименование и удаление из локального списка (`localStorage`), открытие существующей сессии по UUID, настройка рабочего каталога `cwd`.
- **Настройки агента:** выбор режима (`modes`), модели (`models`) и уровня размышлений (`thought_level` из `configOptions`).
- **Автодополнение команд:** всплывающее меню по `/` для `availableCommands` (поддерживает стрелки, `Tab` и `Enter`).
- **Производительность и скролл:** на длинных диалогах отображаются последние 20 сообщений с подгрузкой предыдущих порциями по 20 при прокрутке вверх (с сохранением позиции скролла); умный автоскролл вниз и кнопка «Вниз».
- **Автопереподключение:** отслеживает возвращение на вкладку (`visibilitychange`, `pageshow`) и восстанавливает соединение с пересылкой накопленного буфера.
- **Темы оформления:** светлая и тёмная темы (переключатель внизу боковой панели, по умолчанию берётся системная тема).

### Просмотрщик файлов (`/files`)

- **Просмотр кода и текста:** нумерация строк, подсветка через `highlight.js`, выделение и автоскролл к строкам по якорям `#L10` и `#L10-L20`.
- **Markdown:** встроенный рендер `.md`-файлов с переходом по относительным и `file://` ссылкам внутри просмотрщика.
- **Навигация по директориям:** список файлов и папок с размерами и «хлебными крошками» (breadcrumbs).
- **Режимы просмотра:**
  - `/files?path=...` — HTML-просмотр (по умолчанию);
  - `&raw=1` — чистый `text/plain`;
  - `&download=1` — потоковое скачивание файла (`application/octet-stream`);
  - `&head=1` / `&tail=1` — предпросмотр начала или конца крупных файлов, превышающих `ACP_VIEWER_MAX_BYTES`.
- **Безопасность:** строгий CSP (`default-src 'none'`), `X-Content-Type-Options: nosniff`, определение бинарных файлов, аккуратная обрезка фрагментов по границам UTF-8 символов.

## Структура проекта

```text
web-agent/
├── src/                        # Бэкенд (NDJSON-WS мост и HTTP file-viewer)
│   ├── index.ts                # CLI-точка входа и разбор аргументов запуска
│   ├── config.ts               # Валидация конфигурации и переменных окружения
│   ├── bridge.ts               # WebSocket-мост, detached-режим, буфер, процесс-ридер
│   ├── ndjson-framer.ts        # Инкрементальный парсер NDJSON-строк с лимитом размера
│   ├── message-filter.ts       # Нормализация клиентских JSON-RPC кадров и фильтр $/ping
│   └── file-viewer/            # Встроенный HTTP-сервер /files
│       ├── handler.ts          # HTTP-роутинг, CSP-заголовки, стриминг скачивания
│       ├── path-utils.ts       # Парсинг query, конвертация file://, breadcrumbs
│       ├── file-reader.ts      # Чтение файлов/папок, head/tail-сниппеты, детект бинарников
│       └── render-html.ts      # Генерация HTML-страниц просмотрщика
├── web/                        # Фронтенд (React 19 + TypeScript + Vite)
│   ├── vite.config.ts          # Конфиг сборки и dev-прокси (/ws, /files -> 127.0.0.1:3001)
│   └── src/
│       ├── main.tsx            # Точка входа React-приложения
│       ├── acp/                # Слой протокола ACP (WS-транспорт, RPC-клиент, reducer, типы)
│       ├── hooks/              # useAcpSession.ts — управление жизненным циклом сессии
│       ├── components/         # UI-компоненты чата, сайдбара, шагов, модалки разрешений
│       ├── lib/                # storage, markdown, file-links, clipboard, uuid, pluralize
│       └── styles/             # Дизайн-токены (светлая/тёмная темы) и глобальные стили
├── tests/                      # Unit- и интеграционные тесты бэкенда (Vitest)
├── web/tests/                  # Тесты фронтенда (Vitest + Testing Library + jsdom)
├── deploy/                     # Шаблоны конфигов для Linux-сервера
│   ├── acp-bridge.service      # systemd unit для моста
│   └── nginx-acp-ui.conf       # Nginx-конфиг (статика + /ws + /files)
├── scripts/
│   └── build-web.sh            # Скрипт сборки и выкладки фронтенда в /opt/acp-web/dist-web
└── docs/tasks/                 # Архитектурные описания и RFC этапов разработки
```
